# 行动轨迹与蒸馏工作台

## 正式界面

入口仍为银灰神经看板，光球和 7 个模块水母保留。今日面板打开蒸馏工作台；行动轨迹面板打开证据登记。

## 指标口径

- 不设置综合成长分，也不根据记录减少推断能力下降。
- 近 14 天每日曲线展示明确登记的实践次数，成果另列。
- 积累只统计笔记明确的 `createdAt` 或 `date`；导入目录、`origin: import`、网络摘要单列。
- 无明确日期的旧笔记不使用修改时间推算。旧文件不自动补写日期。
- 实践和成果由用户明确登记，必须关联真实 Markdown 笔记；重复相同登记返回已有记录。
- 能力阶段由用户确认并关联证据，显示该能力最近一次确认，不自动晋级。
- 事件写在 `vault/.progress/events.jsonl`，实际能力需要结合证据判断。

## 蒸馏流程

1. 填写用途，选择待蒸馏或普通笔记，也可粘贴正文。
2. 每 6000 字分块，最大 18 万字；所有块处理后才完成候选阶段。每块保存主旨、参考、缺口和处理范围，失败可用相同素材和用途续跑。
3. 引用必须与对应块原文逐字匹配，且至少 12 字；缺来源或输入输出契约的候选进入待核查，不可选为技能。
4. 选择最多 8 个候选生成草稿。检查触发、输入输出、步骤、完成标准、边界，不强凑字数。草稿保存在 `.distill/`，不会进入技能加载目录。
5. 提供真实任务输入、期望标准和不适用场景，执行模型试跑。试跑不代表已经实际操作外部系统，必须人工核对结果。
6. 填写验收反馈并明确启用，才生成 `agents/skills/distill-<稳定任务ID>/SKILL.md`。同素材同用途返回已有任务，不自动制造 v2/v3。
7. 已启用版本保持不变；要修改需提交更新后的素材或用途。现有历史 Skill 不做批量重写。

原文匹配只证明引用真实存在，不证明该引用必然支持全部生成步骤；工作台保留来源与边界试跑供人工检查。当前试跑是文本能力验证，没有自动执行真实项目或验证实际成效。

工作台提取、生成和试跑使用已配置的云模型，会发送选定素材与输入；没有云密钥时明确报错，不假装已完成。

## 开发工作状态

`node scripts/activity.mjs start 说明` 开始，`renew 说明` 续期，`done` 结束（保留 30 秒“刚完成”）。API 把有效开发租约映射成红色工作态，沿用正式看板现有的红色水母、神经连线与标签。应用内蒸馏任务优先显示。180 秒未续期自动回到原状态，避免异常退出后一直红色。

这是开发流程主动登记，不能自动发现任意外部 AI 会话；项目 AGENTS.md 已规定后续修改时登记、续期与结束。

## 验证

`pnpm test` 覆盖指标分离、租约过期、来源伪造拦截、全文块覆盖、断点续跑和启用门槛。正式前端运行 `npm run verify` 与 `npm run build`；原自检的 5 模块假设已更正为当前 7 模块。

工作状态徽标显示于所有页面顶部；活动轮询禁用缓存。工作态动画不修改水母定位 transform，避免 CSS 动画覆盖场景位置。

## WorkBuddy 工作状态接入

看板每次读取活动接口时，会同时检查 WorkBuddy 的本地 `traces` 运行轨迹；不依赖 WorkBuddy 主动运行 Codex 的登记脚本。只提取任务开始/结束时间、trace ID、worker PID 和文件更新时间，不把对话或工具输入输出发送给模型。

- 有未结束任务、worker 存活且近期有轨迹更新时，显示 WorkBuddy 正在运行任务，沿用红色水母、连线与顶部徽标。
- 任务结束保留 30 秒完成提示；进程退出或 10 分钟无轨迹更新则不继续标记运行。
- 仅打开 WorkBuddy 应用不会标红。Codex 与 WorkBuddy 同时运行时合并显示来源。
- 该桥接依赖当前 WorkBuddy 的本地 trace 格式；升级后若日志位置或格式变化，需要调整适配器。它不会启动、控制或修改 WorkBuddy 的任务。
